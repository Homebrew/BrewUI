# Architecture Decision Records

This directory contains Architecture Decision Records (ADRs) for BrewUI.

An ADR documents a significant architectural or design decision: what was decided, why, and what alternatives were considered. They are lightweight, permanent records that help future contributors (and AI agents) understand *why* the codebase is the way it is — not just *what* it does.

## Format

ADRs are numbered sequentially: `NNNN-short-title.md`. Use `0000-template.md` as your starting point.

## Status Values

- **Draft** — being written, not yet decided
- **Proposed** — ready for review/discussion
- **Accepted** — the decision is in effect
- **Deprecated** — no longer applies but kept for history
- **Superseded by [NNNN]** — replaced by a later ADR

## When to Write an ADR

Write an ADR when:
- You're making a significant technology or framework choice.
- You're choosing between two or more non-obvious approaches.
- You're establishing a pattern that others should follow.
- You're overriding or changing a previous decision.

You don't need an ADR for every small decision — only the ones where the *reasoning* is important to preserve.
